## 2. The nflverse trap that caused the "not found"/stale confusion (critical knowledge)

1. `scripts/monitor/` did not exist before this build - any earlier attempt referencing
   `scripts/monitor/nfl_data_sentinel.py` failed with a literal "not found" file error.
   v1.0.1 ships with the directory created explicitly and every path Test-Path-verified first.
2. GitHub releases in nflverse/nflverse-data are RE-CUT BY RE-UPLOADING ASSETS:
   - `published_at` is stale by YEARS (e.g., stats_player published 2025-07-31, pbp 2022-01-28).
   - The true cut time = `max(asset.updated_at)` across the tag's assets (stats_player was
     re-cut 2026-10-07T16:27:19Z and again 2026-10-08 ~16:35Z).
   - Any monitor comparing `published_at` (or assuming per-tag 404s) gets nonsense staleness
     and false LATE alarms - exactly the failure mode seen before this rewrite.
3. Real tag names (all 25 discovered, `/releases?per_page=100` returns the full repo):
   `stats_player, stats_team, pbp, schedules, rosters, weekly_rosters, depth_charts, injuries,
   pfr_advstats, snap_counts, nextgen_stats, ftn_charting, espn_data, players, players_components,
   draft_picks, contracts, trades, teams, officials, misc, combine, pbp_participation,
   player_stats, test`. NOTE: `pt_spread` does NOT exist in nflverse-data (the module's betting
   sources are not this repo) - the feed was removed after ground-truthing.
4. 554 assets per stats tag (week/reg/post/regpost x years x qs/rds/csv/parquet). The initial
   3-week bundle gap happened because the exporter is a manual step; week 4 arrived when the
   exporter was run, and the 2026-10-08 refresh picked up the overnight correction re-cuts.

## 4. The learning layer (question 4: "machine learning")

All functions are pure, documented and replay-tested offline (15 tests, deterministic):

```
EWMA mean/variance:  mu' = a*x + (1-a)*mu ;  v' = a*(x-mu)^2 + (1-a)*v ;  a = 0.25 (updates only on cuts)
Robust size z:       z = (x - mu) / max(sqrt(v), 0.002*|mu|, 1) ;  alarm |z| > 3, trusted after n >= 5 (warmup logs only)
MAD arrival window:  med = median(hours) ; mad = max(median(|h-med|), 0.5) ; window = med +/- 3*mad (needs 4+ same-weekday cuts)
LATE rule:           prior: after the window closes, no cut since this cycle's window start and hours > late_hours
                     (all-days feeds: pure max-gap) ; learned window replaces the prior automatically
CUSUM drift:         s = max(0, s + (x-mu)/sigma - 0.5) ; alarm s > 5 (sustained upward size drift)
Suppression:         every alarm posts at most once per cut (keyed by cut = max asset updated_at)
```

Alarms: NEW_CUT, LATE, SIZE_ANOMALY, ASSET_MISSING, TAG_MISSING, STALE_BUNDLES,
WEEKS_NOT_CONTIGUOUS, ERROR. STALE_BUNDLES fires when the stats_player re-cut is >36h newer than
our `season_2026.json` and prints the exact refresh runbook in the alert.

## 10. Lessons recorded (do not relearn)

1. nflverse cuts = max(asset.updated_at); published_at is a trap. Never alarm on it.
2. A monitor must degrade gracefully: 404 tag -> TAG_MISSING (or silent for optional), API
   failure -> ERROR event, never a crash; the list endpoint removes per-tag 404 churn entirely.
3. Suppression (one post per alarm per cut) + chatty-feed gate keep the channel trustworthy.
4. CI state must be committed or the cloud run has amnesia (stateless runners).
5. Verify paths with Test-Path and create dirs before writes - the literal "not found" class of
   failure disappears.
6. Docstring paths on Windows: use raw strings (r"""...""") or `\\` to avoid \p/\n escapes.
7. Keep version checks dynamic in verifiers (verify reads sentinel.VERSION, never a literal).
